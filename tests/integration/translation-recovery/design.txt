Translation Queue P1 — proposed SQL, NOT installed in Production

Failure: the legacy Worker saves experience fields and task completion in two
requests. If the second request fails, queued/retryable-only leasing cannot
recover the processing row. No active stuck Production rows were observed.

The new RPC commits experience, completion receipt, task and job together.
The legacy experience UPDATE trigger provides the same transaction boundary
for the protected Worker. Receipts store exact locale fields, task identity and
translation version; a ready metadata flag alone is never a completion proof.
Manual locale fields remain unchanged. The trigger preserves media_revision
assigned by the existing earlier trigger and preserves sibling locale fields.

Legacy task PATCH requests carry no lease token. Reclaim therefore retires the
old task IDs AND advances experience.translation_version before creating a new
job and unfinished-locale tasks. This uses the legacy Worker's existing version
filter as a fence. Terminal row guards prevent late unqualified PATCH requests
from reopening retired/completed tasks or jobs. Retryable tasks also rotate once,
retaining provider/backoff/attempt state. Only one locale lease per experience
is allowed, including across providers. No state-format or DO migration occurs.

The new finalizer locks experience then task, checks task/version/lease identity
and expiry, and is idempotent after commit. An expired finalization throws a
retryable infrastructure error instead of cancelling recoverable work. Provider
outcome failure or lost ACK after commit cannot reopen the completed task or
cause another AI call. An AI request still running when its lease expires may
be repeated by recovery; exactly-once external AI execution is not claimed.
Its late result cannot overwrite the recovered generation.

Installation is selective and transactional: lock_timeout 5s, statement_timeout
60s, exact pre-existing lease function body hashes, and no leased/processing
rows. A failed precondition rolls back all installation work. The existing
migration ledger, historical baseline, financial SQL and Runtime files are not
modified or replayed in Production. No historical row repair is installed.
The SQL advances versions only later when a normal Worker wake reclaims work.
Existing provider limits, public RPC object IDs/dependencies and both lease overload return shapes remain. Superseded source-version tasks are cancelled on normal recovery wakes and excluded from dispatch, so they cannot starve current work.
